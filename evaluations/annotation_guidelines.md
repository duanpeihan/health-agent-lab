# Claim Verifier 四分类标注规范（候选版）

**用途与边界。** 本文件是 `health-agent-lab` 针对“主张 + 本次实际传入的证据”制定的项目规约，**不是唯一正确的通用事实核查标准**，也不判断主张在现实医学中的真伪。标注者只使用该案例给出的事实原文；不补用外部常识、来源标题、未传入的知识库条目或模型生成的解释。现有 WHO/CDC 摘录未在此接受医学专家或来源现行性审核。合成歧义夹具仅测试语言判断，不是医学建议。

## 标注单元与操作

1. 逐字读取主张和实际输入的每条 `facts`，确认人群、时间、单位、强度、量词、否定、条件、建议/观察/疗效的性质。一个案例可能含多个必要子断言；先分别核对，再给整条主张一个标签。
2. 不把“证据提到了相同数字/词语”当作支持；必须核对数字的上下界、对象和语义角色。例如观测均值不自动成为推荐量。
3. 先判断证据是否**明确留下与主张结论有关的多个未决解释**。对每个合理解释分别问：主张被支持、被反驳，还是仍缺证据？
4. 若所有相关解释都直接支持，标 `supported`；若所有相关解释都在相同条件下直接反驳，标 `contradicted`。若证据明确未决、且不同解释会改变主张能否成立，标 `uncertain`。
5. 其他情况标 `not_supported`：包括未提及、缺少关键属性、越过人群或时间范围、把建议升级为保证疗效，以及仅凭更强的数字或量词作推断。没有证据时也归此类。
6. 若多条证据在关键事实或版本上直接冲突且无法确定采用哪条，按显式未决处理；不要挑一条方便的证据。若其中一条明确是最终版本，则优先按最终版本判断。

上述顺序是一套**可复核的操作约定**。遇到一条复合主张的某子断言直接矛盾、另一子断言缺证据时，应在理由中拆开说明；通常以直接矛盾的关键子断言标 `contradicted`。若无法确定哪部分是核心，应标记争议，交人工裁决，不暗改原始数据。

## 四类定义和边界

### `supported`：直接支持

给定证据在主张的关键限定上直接蕴含它。允许保持原意的同义改写、从“甲或乙”中抽取其中一个明确选项，以及不改变限定条件的简化表述。证据必须覆盖主张的每个实质子断言。

- 证据“可以从少量活动开始并逐步增加” → 主张“先少量开始，再一步步增加”：`supported`。
- 证据给出高强度活动 75–150 分钟作为两个建议选项之一 → 主张说它是其中一种选择：`supported`。
- **反例**：证据只说“至少 7 小时”，主张说“必须 12 小时”；12 小时虽满足下界，证据没有给出更强的必要性，应为 `not_supported`。
- **反例**：证据只给观察均值，主张说这是推荐值；不能仅凭数字相同标支持。

### `contradicted`：相同条件下直接冲突

把主张与证据对齐到相同人群、时间、建议/事实口径后，二者关键断言不能同时成立。明确否定、互斥区间、明确“而不是”替换给定推荐、应做与不应做、全部相同与明确不同，属于此类。须引用造成冲突的原文。

- 证据“18–60 岁通常建议每晚**至少** 7 小时” → 同口径主张“建议**少于** 7 小时，**而不是至少** 7 小时”：`contradicted`。
- 证据“150–300 分钟中等强度活动是推荐区间” → 主张“推荐量是 15–30 分钟，**而不是** 150–300 分钟”：在本项目规约下为 `contradicted`（C002）；人工应复核“推荐量”的排他性解释。
- **反例**：证据“通常建议至少 7 小时”与主张“必须 12 小时”可以同时成立，但后者推不出；不能只因数字不同就判矛盾。
- **反例**：证据只限定 18–60 岁，主张改说 65 岁以上；人群越界通常是 `not_supported`，不是直接冲突。

### `not_supported`：不足以推出，且无约定的显式歧义

证据没有涉及关键内容，或仅支持主张的一部分；主张引入了新的人群、数值、疗效、因果、保证或更强量词，而证据没有直接反驳。**单纯信息缺失不是 `uncertain`**；必须检查下面的显式歧义门槛。空证据也归本类。

- 证据只有睡眠时长与质量条件，主张称拉伸 20 分钟让所有人的入睡时间减半：`not_supported`。这不是对现实疗效的否定。
- 证据给出成年人每周至少 2 天力量训练建议，主张称每周锻炼两天保证每个人长寿：`not_supported`；不得把建议改写成“证据证明有益/保证长寿”。
- 证据“部分人”不推出“所有人”；若没有明确“并非所有人”，一般为 `not_supported`。
- **反例**：证据明确列出两个待选最终版本且未决定，主张断言选了其中一版；按本规约不是普通缺证据，而是 `uncertain`。

### `uncertain`：证据明确相关歧义且未解决

证据**明确**保留与主张相关的两个或多个候选版本、指代、量词范围、分母、数据性质或逻辑解释，且这些解释可能使主张成立与不成立。相关选项必须出现在输入证据中；不因为标注者或模型“自己不确定”就选此类。

- 草稿 A 为 2 天、草稿 B 为 3 天，最终版本未记录；主张断言最终为 3 天：`uncertain`。
- “20%”的分母明确可能是全体或甲组；主张断言全体：`uncertain`。
- “成年人”在证据中明确可能指全部也可能仅部分；主张断言所有：`uncertain`。
- 表格“7 小时”明确可能是建议值也可能是观测均值；主张断言推荐值：`uncertain`。
- **反例**：证据完全没有提到牛奶和失眠治疗，主张称牛奶治愈失眠；不存在相关候选解释，为 `not_supported`。
- **反例**：证据虽有模糊措辞，但所有合理解释都支持（或都反驳）主张，应标 `supported`（或 `contradicted`），不因表面含糊就标 `uncertain`。

## 高频混淆核对表

| 问题 | 本项目建议 |
|---|---|
| “可能支持”能否算支持？ | 不能。需所有关键限定得到确定证据支持。 |
| “未证实”是否等于“被反驳”？ | 不等于。只有相同条件下直接互斥才是 `contradicted`。 |
| “缺少最终选择”是 `not_supported` 还是 `uncertain`？ | 若证据**明确给出相关待选版本**且选择未决，按本规约为 `uncertain`；这是需人工确认的项目边界。 |
| 数字不同是否必然冲突？ | 否。先区分下界、上界、区间、唯一值、单位和建议口径。 |
| “有些”能否推出“所有”？ | 不能；若证据明确“部分且非全部”则可直接冲突，否则通常是 `not_supported`。若来源明确“全部或部分未定”，是 `uncertain`。 |
| 模型理由或引用影响标签吗？ | 不直接影响原始标签；分类一致、引用有效、解释忠实度分别评估。 |

## 标注记录与升级

每条保存原始标签及理由、实际输入证据、建议标签、争议说明。人工最终标签与复核意见保持空白，待独立审核者填写；Agent 的建议不能写入人工栏。争议优先复核 U001–U006、H-U01/H-U02，以及 C002、N001 等数字/量词边界。若人工改变标签，发布新版本的数据集与变更记录，保留原始 24 条、8 条保留集和所有历史结果，重新计算探索性指标时注明标签版本。
